## 1. このゲームは何か

プレイヤーは、問題をかかえた小さな会社を引き継ぎ、**組織の形を変えて、仕事が期限内に終わるようにする**。【決定】

- 面白さの中心:仕事がどこで詰まっているかを見つけ、組織を変えて直すこと。
- お金・商品・売上の管理は中心にしない。
- 最小版で確かめたい問い:**「組織を変える → 結果が変わる → 原因が分かる」のくり返しは面白いか。**

### 1-1. 固定の目標(1つだけ)【決定】

**期限内完了率** = 期限をむかえた業務のうち、期限までに完了した業務の割合。

- 測り方:直近30日に期限をむかえた業務で数える。期限を過ぎてもまだ終わっていない業務は「期限内でない」に数える。
- 制約:**人件費の上限**をこえてはいけない(目標ではなく、守る条件)。
- ほかの数字(平均の処理日数、差し戻しの件数など)は、原因を探すための表示であり、目標にはしない。

### 1-2. 方針【決定】

- 面白さに効く因果だけを入れる。「現実らしさ」だけが理由の仕組みは後回しにする。
- 実在の会社・人物・制度の名前は使わない。会社も職員も架空にする。【案】
- 人を減らす操作は最小版に無い。あとで足すときは「人員削減」として数字で淡々と扱う。ハラスメントなどは扱わない。【案】

## 3. ゲームの中身【案】

この章の式と数字は、AIの提案です(会社の種類・業務の種類・部署の作り方は k さんが決めました。7章)。

### 3-1. 会社の部品

**職員**
- 名前(架空)、所属する部署(1つ)、専門能力(分野ごとに1〜5)、管理能力(1〜5)を持つ。
- 分野は3つ(営業・制作・検査)。最初の会社では、主な分野の専門能力は2〜4(部署の平均がほぼ3)、ほかの分野は2。

**部署**
- 名前、部署長(1人。空席もありうる)、所属する職員、担当する工程を持つ。
- 部署は別の部署の下に入れられる(入れ子)。
- **工程を担当する部署の職員と、その下の部署の職員が、その工程の作業をする**。これで「制作部を分けて、部署長の管理を楽にする」ができる。分けた部署にも部署長が要り、部署長は作業をしないので、人件費が増えて作業する人が減る。

**社長**
- 職員の1人。一番上の部署長たちの上司。承認もできる。プレイヤーは社長を動かすのではなく、組織の形を決める立場。

**上司の決まり方**
- 職員の上司は、所属する部署の部署長。
- 部署長の上司は、1つ上の部署の部署長。上が無ければ社長。
- つまり「上司を決める」操作は、「部署長を任命する」と「部署をどの部署の下に置くかを決める」の2つ。

### 3-2. 業務

- 業務の種類ごとに、工程の順番が決まっている。
- 工程ごとに、必要な分野と作業量(人日)が決まっている。
- 業務は毎日、決まった件数の前後で発生する。発生したときに期限(発生から何日後か)が付く。
- 最後の工程が終わり、ミスが残っていなければ「完了」。

**職員の専門分野は「営業・制作・検査」の3つ**【決定】。工程と1対1で対応する(営業=見積、制作=制作、検査=検査)。

**業務の種類は3つ**【決定】。数字は【仮の値】で、ボットで調整する。

| 種類 | 工程と作業量(人日) | 期限 | 発生(件/日) |
|---|---|---|---|
| 小口注文 | 見積0.5 → 制作2 → 検査0.5 | 10日 | 2.6 |
| 大口注文 | 見積1 → 制作8 → 検査2 | 25日 | 0.54 |
| 急ぎ注文 | 制作1.5 → 検査0.5(見積なし) | 5日 | 0.86 |

発生の件数は平均で、実際は日ごとに前後する(固定シードで毎回同じ)。

### 3-3. プレイヤーが決めること

1. **配置**:どの職員をどの部署に置くか。
2. **上司**:部署長を誰にするか。部署をどの部署の下に置くか。
3. **担当**:どの工程をどの部署が担当するか。
4. **承認**:工程ごとに、終わったあと誰が確認するか。「承認なし」「部署長」「その上の上司」から選ぶ。
5. **部署の新設・廃止**:部署を作る(場所と名前を決める)。職員のいない部署を無くす。職員がいる部署は、先に職員を動かしてから無くす。

変更は、一時停止中でも進行中でも、いつでもできる。

### 3-4. 1日の計算の順番(ここ1か所だけに書く)

1. 新しい業務が発生し、最初の工程を担当する部署の「待ち」に入る。
2. 部署長と社長が、その日の時間を「管理」と「承認」に使う。
3. 職員が、所属部署の待ちの中から期限が近い順に業務を取り、作業を進める。
4. 工程の作業が終わった業務について、ミスが出たかを決める。
5. 承認が必要な工程は「承認待ち」に入る。承認者は時間があれば確認し、ミスを見つけたら差し戻す。
6. 承認を通った業務(または承認なしの業務)は、次の工程の担当部署へ渡す。
7. 最後の工程を通った業務にミスが残っていれば、客からの差し戻しになる。残っていなければ完了。
8. その日の数字を記録する。

計算は必ず1日ずつ行う。速度を上げても、何日分かをまとめて計算することはしない。

### 3-5. 式【案】(数字は全部【仮の値】)

**職員の1日の作業**
- 1人が1日に使える時間は 1.0人日。
- 進む作業量 = 使った時間 × 能率。
- 能率 = (その分野の専門能力 ÷ 3) × 管理の効き × 習熟。
  - 専門能力3がふつう(能率1.0)。能力1なら約0.33、能力5なら約1.67。

**管理の効き(管理の幅)**
- 部署長は、直属の部下1人につき 1日 0.11人日 を管理に使う。管理能力が高いほど少なくて済む(必要な時間 = 0.11 × 3 ÷ 管理能力)。部下には、下の部署の部署長も数える。社長も同じで、部下は一番上の部署の部署長たち。
- 管理に必要な時間が足りているとき、管理の効き = 1.0。
- 足りないとき、足りない割合に応じて、部下全員の管理の効きが最大で 0.47 まで下がる(効き = 1 − (1 − 0.47) × 足りない割合)。
- 部署長が空席のとき、管理の効き = 0.47。
- 部署長は自分では作業をしない(管理と承認だけ)。

**承認**
- 承認1件に、承認者の時間を 0.05人日 使う。
- 承認する人:「部署長」=その工程を担当する部署の部署長(空席なら上の部署の部署長、誰もいなければ社長)。「その上の上司」=1つ上の部署の部署長(なければ社長)。
- 部署長は、管理を先にして、残った時間で承認する。時間が足りないぶんは翌日に持ちこす(これが「承認待ち」)。
- 承認者がミスを見つける確率 = 50% + 管理能力 × 8%(管理能力5で90%)。

**ミス**
- 工程が終わるたびに、ミスが出る確率 = 33% − 専門能力 × 5%(能力3で18%、能力5で8%)。
- 承認で見つかったミス:その工程をやり直す(作業量の半分)。
- 最後まで見つからなかったミス:客からの差し戻しになり、ミスの出た工程を全部やり直す。期限は変わらない。
- ミスの影響は「やり直しの作業」として1回だけ数える(品質の点数などを別に作らない)。

**受け渡し**
- 承認なしの工程が終わったとき:同じ部署の次の工程は、その日のうちに着手できる。別の部署へ渡すときは、次の日から(1日かかる)。
- 承認を通ったとき:次の日から着手できる。別の部署へ渡すときは、さらに1日かかる。
- 承認で見つかったミスのやり直しは、同じ部署で、次の日から。

**異動の習熟**
- 部署を移った職員は、5日間、習熟 = 0.5。それ以外は 1.0。

**人件費**
- 職員:1日 1.0給与単位。部署長:1日 3.0給与単位。社長:数えない。
- 人件費の上限 = シナリオ開始時の人件費(31)× 1.1 = 34.1。上限をこえる変更はできない。部署長を1人増やすと +2.0 なので、増やせるのは1人だけ。

### 3-6. この仕組みで生まれるはずの「悩みどころ」

仕組みが正しく動けば、次のような、どちらにも良い面と悪い面がある選択が生まれる。ボットと実際のプレイで、本当にそうなるかを確かめる。

| 選択 | 良い面 | 悪い面 |
|---|---|---|
| 部署を細かく分ける | 部署長の管理が行き届く | 部署長が増えて作業する人が減る。人件費が増える。受け渡しが増える |
| 1つの部署に工程をまとめる | 受け渡しの待ちが無い | 部署長の管理が足りなくなる |
| 承認を増やす | ミスを早く見つけられる | 承認待ちができる |
| 承認を上の人に任せる | ミスを見つけやすい人が確認する | その人に承認が集中して詰まる |
| 人を忙しい部署へ動かす | 詰まりが減る | 数日は能率が下がる。元の部署が弱くなる |

## 4. シナリオ【案】

- 架空の制作会社を1つ用意する。**社長+職員25人、部署は3つ**【決定】。どこかに詰まりがある状態で始まる。
- 期間は90日【決定】。

**最初の会社**【決定】(部署長も職員25人に含む)

| 部署 | 職員 | 部署長 | 最初の詰まり |
|---|---|---|---|
| 営業部 | 6人 | 1人 | 余裕がある |
| 制作部 | 14人 | 1人 | 部署長1人に部下13人。管理時間が足りず、管理の効きが下がる |
| 検査部 | 5人 | 1人 | 余裕がある |

- 全工程の承認は、最初は社長に集まる設定にする。承認が社長で詰まる。
- **引き継ぎ時の状態**:過去30日に期限をむかえた業務の約60%が期限内(引き継ぎ時の完了率の目安)。いま、期限がこれからの業務のうち半分ほどが、途中でたまっている(17〜21件ほど)。
- 部署は上限8つまで。部署は、人がいなくても、部署長が空席でも作れる。作る・無くすのに費用も日数もかからない(部署長を任命した分だけ人件費が増える)【決定】。空席の部署は管理の効きが 0.47 に下がる(3-5)ので、むやみに増やしても得にならない。
- 業務の発生量は、**最初の会社で期限内完了率が約60%になる量**にする【決定】。何もしないと失敗し、うまく直すと80%に届く幅をつくる。3-2 の数字は、ボットの測定(`docs/測定結果.md`)で合わせた仮の値。
- 成功:最後の30日間の期限内完了率が 80%以上【仮の値】で、人件費の上限を守っている。
- 90日が終わると結果の画面を出す【決定】。期限内完了率と人件費を見せ、「成功/惜しい/失敗」の3段階で表示する(成功:80%以上で人件費の上限内。惜しい:65〜80%。失敗:65%未満または人件費の上限超え。境目は【仮の値】)。
- 途中でゲームオーバーにはしない。結果を表示して、やり直せる。
- 始める前に、会社の状態を一言だけ見せる(例:今は60%、目標は80%)【決定】。長い説明は入れない。
- 業務の発生とミスには運(乱数)を使うが、同じシナリオは毎回同じ展開になるようにする(固定シード)。

## 5. 時間と画面【案】

**時間**
- 1日 = 計算1回。休日は作らない。
- 一時停止・通常・高速の3つ。指定した日数だけ進める機能は最小版に入れない。始めるときは一時停止で始まる。

**画面(スマホの縦向きを基本にした1画面。パソコンでも同じ縦並びで、幅は広げすぎない)**【2026-11-21 変更】
- 上に固定で、期限内完了率(大きく。目標の80%以上なら緑、未満なら赤)・日付と進み具合・人件費(上限つき)・速度ボタン(押しやすい大きさ)。
- その下に、全体の数: 作業中・承認待ち・期限をすぎた件数。
- 部署は縦に並べたカードで見せる(下の部署は字下げ)。カードには、部署名・人数・部署長・受け持つ工程と、**待ちの棒**(余裕あり=緑・期限が近い=黄・期限をすぎた=赤を、件数に比例した幅で並べる)を出す。**詰まりが目で見て分かること**を最優先にする。
- 部署のカードをタップすると、待ちの内訳と職員の名前が出る。
- 業務を選ぶと、その業務の履歴が出る(どの部署で何日待ったか、何回差し戻されたか)【実装6】。
- 変更前の案「組織図の上を業務の粒が部署から部署へ動く」は、スマホの狭い画面では読めないため、やめた。

**作業の順番**
- 職員は、部署の待ちから**期限が近い順**に業務を取る。部署ごとに優先方針を選ぶ機能は最小版に入れない【決定】。

**原因の表示**
- 遅れた業務について、かかった日数を「作業」「作業の順番待ち」「承認待ち」「受け渡し」「やり直し」に分けて見せる。
- ゲームから「こう直すとよい」という提案は出さない。

**保存**
- ブラウザの中に自動保存を1つ。保存先の名前に題名や版の番号を入れない。

## 6. 単位と用語

### 6-1. 単位の表

| 数字 | 単位 | 何を何で数えるか |
|---|---|---|
| 時間 | 日 | 計算1回 = 1日 |
| 作業量 | 人日 | 能力3の職員1人が1日で進められる量 = 1人日 |
| 職員の時間 | 人日 | 1人が1日に使える時間 = 1.0人日 |
| 専門能力・管理能力 | 1〜5の段階 | 3がふつう |
| 期限 | 日 | 業務が発生した日から数えた日数 |
| 期限内完了率 | % | 期限内に完了した件数 ÷ 期限をむかえた件数(直近30日) |
| 人件費 | 給与単位/日 | 職員1人の1日ぶん = 1.0給与単位 |
| 業務の件数 | 件 | 業務1つ = 1件 |

お金は最小版では人件費だけなので、円ではなく「給与単位」を使う。

### 6-2. 用語の表(この言葉だけを使う)

| 使う言葉 | 意味 | 使わない言葉 |
|---|---|---|
| 職員 | 会社で働く1人 | 人員、個人、社員、メンバー |
| 部署 | 職員のまとまり。大きさに関係なく全部「部署」 | 部門、課、チーム、組織単位 |
| 部署長 | 部署の長。その部署の職員の上司 | 管理職、マネージャー |
| 上司 | 自分を管理する1人 | 直属上司、指揮命令者 |
| 業務 | 会社に入ってくる仕事1件 | 案件、仕事、タスク |
| 工程 | 業務の中の1つの段階 | 段階、ステップ |
| 担当 | 部署がある工程を受け持つこと | 割り当て |
| 承認 | 工程が終わったあとの確認 | 検査、チェック、専門確認 |
| 差し戻し | ミスが見つかって工程をやり直すこと | 手戻り、再作業、やり直し |
| 待ち | 部署にたまっている未着手の業務 | 滞留、未処理 |
| 期限内完了率 | 固定の目標(1-1) | 円滑さ、効率、総合評価 |

### 6-3. つまみの表(調整できる数字)

数字は全部【仮の値】。仕組みを確認したあと、この表を見ながら調整する。変えたら `決定ログ.md` に理由を1行書く。

| つまみ | 今の値 | 理由 |
|---|---|---|
| 部下1人あたりの管理時間 | 0.11人日 | 管理能力3の部署長が、部下9人ほどで手一杯になる値。制作部の13人だと足りなくなる(2026-11-21 に 0.08 から変更) |
| 管理不足・空席のときの効きの下限 | 0.47 | 部署を分ける操作の効きが、はっきり見える程度(0.7 から変更) |

## 8. 測る道具(最小版と一緒に作る)

- **見本の会社**:シナリオの会社を固定のデータとして持つ(`src/sim/scenario.ts`)。シード5つ(1〜5)が標準の設定。

- **確認すること**(`src/bot/bot.test.ts` で毎回自動で確かめる):引き継ぎ時の完了率が約60%/何もしないと失敗/見本の直し方は全シードで成功/1つの操作だけで全部解決する抜け道が無い/主な数字が0や100%に張り付いていない。
- **プレイ記録**:操作・日ごとの数字・速度の変更を記録し、画面の「記録をコピー」ボタンで取り出せるようにする(画面のPRで作る)。
