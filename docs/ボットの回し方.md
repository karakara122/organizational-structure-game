# ボットの回し方

ボット(自動で遊ぶプログラム)は、ゲームの数字を測る道具です。ゲーム本体には入りません。手順は、この文書の1か所だけに書きます。

## 標準の設定(いつもこれを使う)

- シード:1・2・3・4・5(最初の会社の乱数)
- 日数:90日
- 「人を動かす」ボットの行動間隔:5日ごと
- 定義は `src/bot/bots.ts` の `STANDARD_PROFILE`。変えたら、`src/bot/bot.test.ts` の「標準の設定」の確認も同じ回に直す。

## 回し方

- 測定の表を出す:`npm run measure`(数十秒)。出力を `docs/測定結果.md` に貼る(前の表は「調整前」として残す)。
- ゲームとして成り立つかの確認:`npm test`。数字(`src/sim/params.ts`)を変えたら、必ず回す。

## ボットの種類

| ボット | やること |
|---|---|
| 何もしない | 何も操作しない |
| 待ちの多い部署へ人を動かす | 5日ごとに、職員1人あたりの待ちが多い部署へ、少ない部署から1人動かす |
| 見本の直し方 | 最初に1回だけ:見積は承認なし、制作は社長が承認、検査は部署長が承認。制作部の下に部署を作って6人を移し、部署長を置く(あとは放置) |
| 見本の直し+繁忙期に対応 | 見本の直し方のあと、繁忙期の始まりに、営業部の制作が得意な2人を制作部へ動かし、繁忙期が終わったら営業部へ戻す(繁忙期は `params.ts` の `SURGES` から読む) |
| 抜け道を探す(6つ) | 極端な形を最初に1回だけ試す:承認を全部なし/全部部署長/制作部を分ける/営業から3人を制作へ/部署長を全員空席/部署を上限まで増やす |

## 「止まった」を見つけたとき

`detectStuck` が、完了が15日続けて0で、業務がたまっている日を見つけ、理由(承認待ちの件数など)を返します。止まった所は、ゲームの設計の穴を探す材料にします。

## 新しいボットや設定を足すとき

1. `src/bot/bots.ts` に足す。
2. `src/bot/bot.test.ts` にも登録する(標準の設定を変えるときは、そこの確認も直す)。
3. この文書の「ボットの種類」の表に1行足す。
